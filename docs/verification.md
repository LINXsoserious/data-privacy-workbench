# v0.1 本地验证记录

日期：2026-10-25。以下是助手在开发环境执行的验证，不是用户本人独立完成的记录，也不表示生产数据上的识别准确率。

## 环境

- Windows，Python 3.12.3。
- Streamlit 1.66.1、Pandas 3.1.0、OpenPyXL 3.1.5。
- 独立虚拟环境；未修改全局 Python 环境。
- 不使用模型、API 密钥或付费资源。

## 自动化验证

命令：`python -m unittest discover -s tests -v`。

结果：24 项测试全部通过。

- 12 项：候选匹配、重叠处理、校验位与日期、多片段替换、取消误报、原始数据保持不变、陈旧位置拒绝和报告最小化。
- 9 项：编码兼容、前导零和 NA 保留、表头与输入上限、XLSX 公式文本处理、损坏文件拒绝、CSV 公式前缀防护。
- 3 项：Streamlit 内置样例扫描、处理模式与原文对照、切换规则后清除旧结果。

核心先以未实现的函数运行，观察到断言失败，再实现并转为通过。后续检查发现句末英文句号邮箱漏报和超长表头未拒绝，分别补充失败用例后修复。

另生成了与界面 10 / 2 状态一致的合成导出文件，检查误报原值保留、已选手机号被处理、JSON 不包含原始完整命中值。上游许可证与参考源码按固定提交下载并记录 SHA-256；参考源码原有的尾随空格按原样保留，不属于本项目新增代码的格式检查范围。

Streamlit AppTest 在普通测试进程输出 `missing ScriptRunContext` 提示；各测试未产生应用异常。本文件记录本地验证；云端 CI 结果请查看 [GitHub Actions](https://github.com/LINXsoserious/data-privacy-workbench/actions/workflows/tests.yml) 的实际运行，工作流配置本身不作为通过证据。

## 浏览器验证

使用实际运行的 Streamlit 页面验证：

1. 页面载入合成示例，扫描显示 6 条数据、12 个候选、默认处理 11 个、保留 1 个。
2. 取消第 3 条数据中订单号候选的勾选，页面更新为处理 10 个、保留 2 个。
3. 处理后表格保留该订单号原值，其他已选手机号仍显示掩码。
4. 页面提供专用 CSV 与 JSON 下载按钮，原文表格默认隐藏。
5. 实际截图保存为 `docs/screenshot.png`；截图是误报复核之后的 10 / 2 状态。

CSV / XLSX 输入解析和下载内容由自动化测试直接验证；浏览器检查确认了渲染与交互，不代表已验证所有浏览器或所有文件类型变体。

## 已知边界

- 无真实业务数据集上的质量评测，未报告准确率或召回率。
- 未覆盖所有敏感信息类型；格式候选仍需复核。
- 身份证校验不核实行政区和签发身份。
- 未勾选的候选会原样出现在处理后数据中。
- 掩码不是匿名化，报告中的掩码预览仍保留部分特征。
- 公开部署、GitHub 云端测试与用户本人修改能力不由本次本地通过结果推导。
